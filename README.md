# MountainPilot

MountainPilot is an energy-aware route-planning and closed-loop driving-simulation portfolio
project for intelligent-driving and intelligent-cockpit software roles. It demonstrates a complete,
testable chain from a constrained natural-language preference to graph search, vehicle control,
offline simulation, and repeatable evaluation.

> Safety: this is an educational simulation project. It must not control a real vehicle.

## What is implemented

- Directed road graph with road closures, slope, curvature, risk, and speed-limit attributes.
- Dijkstra and A* global planners with deterministic route reconstruction.
- Simplified EV traction-energy model and `fast`, `eco`, and `comfort` cost profiles.
- Rule-based behavior state machine for cruise, following, stop, replanning, and arrival.
- Longitudinal PID, lateral Pure Pursuit, and a kinematic bicycle model.
- Dependency-free offline closed-loop simulator; CARLA remains an optional integration boundary.
- Chinese/English cockpit preference parser with schema validation and a conservative fallback.
- Three repeatable benchmark scenarios exported to JSON and CSV.
- 30 milestone devlogs and 32 unit/regression tests.

## Quick start

Requires Python 3.10 or newer. From the repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m unittest discover -s tests -v
```

Run an end-to-end cockpit-to-route demo:

```powershell
python scripts/run_demo.py --request "帮我选择一条省电而且安全的路线"
```

Generate benchmark evidence:

```powershell
python scripts/run_benchmark.py --output-dir results/latest
```

Expected artifacts are [benchmark.json](results/latest/benchmark.json) and
[benchmark.csv](results/latest/benchmark.csv).

## Architecture

```text
Natural-language request
        |
        v
validated cockpit preference (fast / eco / comfort)
        |
        v
road graph -> energy-aware cost model -> Dijkstra / A*
        |                                  |
        |                                  v
        +----------------------------> route waypoints
                                           |
                                           v
behavior FSM -> PID + Pure Pursuit -> kinematic simulator
                                           |
                                           v
                           safety / efficiency / comfort evidence
```

The cockpit parser cannot emit throttle, brake, or steering commands. It can only select a validated
route profile. See [architecture.md](docs/architecture.md) for module boundaries and limitations.

## Reproducible results

The included demo graph contains a short steep route and a longer flatter route. The current
benchmark demonstrates profile-dependent selection and road-closure replanning:

| Scenario | Profile | Selected route | Distance | Estimated energy |
|---|---|---|---:|---:|
| Fast profile | fast | A -> B -> C -> F | 122 m | 44.92 Wh |
| Energy-aware | eco | A -> D -> E -> F | 141 m | 23.16 Wh |
| A-D closed | eco | A -> B -> D -> E -> F | 162 m | 29.49 Wh |

Numerical outputs are regenerated by `scripts/run_benchmark.py`; the energy model is simplified and
is not a certified vehicle-consumption estimator.

## CARLA boundary

The codebase and CI do not require CARLA. To probe a separately installed, version-compatible CARLA
server:

```powershell
python scripts/probe_carla.py
```

Configuration uses `CARLA_HOST`, `CARLA_PORT`, and `CARLA_TIMEOUT_SECONDS`. A missing client or server
is reported separately from a source-code test failure.

## Current limitations

- Offline road geometry uses sparse point-to-point waypoints rather than CARLA lane topology.
- The energy model omits battery temperature, HVAC, detailed motor maps, and traffic uncertainty.
- Following and stop behaviors are unit-tested state-machine decisions, not a perception system.
- No real vehicle, public-road, or safety-certified deployment is supported.
